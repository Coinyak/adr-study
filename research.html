RESEARCH NOTE · PHARMACOVIGILANCE CAUSALITY BOT

ADR 인과성 평가 봇 설계를 위한 주관성·정책 세팅값 분석

약물이상반응(ADR) 인과성 평가는 평가자·기관·목적에 따라 결과가 달라지는 고질적인 평가자 간 변이(Inter-rater variability)를 가집니다. 본 연구 노트는 제4차 약물부작용 심화교육 2강 사례 분석과 국제 규제기관(ICH·FDA·EMA·WHO-UMC·KIDS) 기준을 토대로, 평가 봇이 단일 정답을 강요하지 않고 사용자가 정책 세팅값을 명시적으로 선택할 수 있게 하는 12개 파라미터와 실시간 시뮬레이터를 정리합니다.

목적: 연구용 · 봇 정책 스키마 설계 참조: 2강 4개 증례 · WHO-UMC · ICH E2A/E2D · EMA GVP VI · FDA · KIDS
Section 01

문제 제기: 왜 단일 정답 ADR 평가 봇은 배포하기 어려운가?

임상 현장의 ADR 평가에는 수학적 참값(Gold standard)이 존재하지 않습니다. 동일한 의무기록을 놓고도 ① 어떤 도구를 쓰는지(WHO-UMC vs 한국형 알고리즘 vs Naranjo vs RUCAM), ② 병용약·기저질환을 얼마나 엄격하게 배제하는지, ③ 단회 투여나 응급처치 후 회복을 Dechallenge로 인정하는지에 따라 Probable과 Possible, 심지어 Unlikely까지 갈립니다.

따라서 봇을 설계할 때 가장 먼저 해야 할 일은 목적이 다른 세 가지 행위를 분리하고, 평가 단계의 주관적 판단 축을 명시적 설정값(Configurable Policy)으로 외부화하는 것입니다.

1단계 · Reporting

부작용 보고 (KAERS / FDA / EMA)

원칙: 최대한 넓게 수집. ICH E2D·EMA GVP VI의 Implied Causality 원칙상 의심되는 자발 보고는 임의로 누락하지 않으며, 병용약이 겹치면 복수 의심약(Suspect)으로 기재합니다.

2단계 · Causality

인과성 평가 (WHO-UMC / 패널 합의)

원칙: 냉정하고 보수적으로. 실제 Dechallenge 여부와 대체원인(출혈·감염·병용약)을 엄격히 검증하며, 확신이 부족하면 억지로 올리지 않고 Possible에 둡니다.

3단계 · Labeling

환자 알레르기 라벨링 (7·12강)

원칙: 가장 신중하게. 막연한 Possible로 β-lactam 금기 라벨을 달면 수술부위감염·MSSA 사망률·내성균이 증가하므로, 보고와 라벨링은 반드시 분리해야 합니다.

Section 02

권위 있는 기관들은 실제로 어떻게 평가하는가?

실제 글로벌 규제당국과 공적 심사기관은 범용 점수표(한국형·Naranjo)의 기계적 총점으로 최종 결정을 내리지 않습니다. 기관별 실제 운영 방식은 다음과 같습니다.

기관 / 표준 평가 방식 병용약 · 불확실성 처리 원칙 봇 설계 시사점
ICH E2A / E2D
FDA · EMA GVP VI		 이분법 (Binary)
Related vs Not Related
(Reasonable possibility)		 자발적 보고는 Implied Causality로 간주(보고 누락 방지). 점수표 비권장. 개연성 있는 병용약은 모두 Suspect로 복수 기재. 규제 보고용 프리셋은 6단계 대신 이분법 + 복수 의심약 모드를 지원해야 함.
WHO-UMC 총체적 판단
(Global Introspection, 6단계)		 Certain=타 원인 0%(cannot be explained) / Probable=타 원인 가능성 적음(unlikely) + 실제 Dechallenge 필수 / Possible=타 원인 설명 가능 OR Dechallenge 불명확. Probable은 병용약 가능성 0%를 요구하지 않으나, Dechallenge 부재 시 Possible 하향이 정석.
국내 KIDS
(피해구제 심사)		 WHO-UMC + 다학제
전문위원회 합의		 개별 점수표 합산이 아닌 의무기록·약동학·역학근거(Bradford-Hill 등)를 종합해 전문위 합의 판정. 봇은 단일 점수보다 근거·반론 요약 리포트를 생성해 인간 전문가(HITL) 합의를 지원해야 함.
장기별 전용 도구 DILI: RUCAM / DILIN 합의
SCAR: ALDEN / RegiSCAR
백신: WHO AEFI		 다제 항결핵제(DILI)나 다약제 노출 SJS/TEN처럼 범용 도구가 무력한 영역에서는 약물 반감기·특이 패턴 기반 전용 기준 사용. 봇 내부에 장기·반응 유형별 라우터(Router)를 두고 DILI/SCAR/백신 전용 모듈 분기 필요.
범용 점수표
(한국형 v2.0 · Naranjo)		 항목별 가감점 합산 평가자 간 일관성은 높으나, 단회 투여·첫 주입 특이반응·응급처치 병행 시 점수가 왜곡되고 병용약 항목이 극단적 양분(+2 vs -3). 최종 결정기가 아닌 항목 누락 방지용 보조 체크리스트로 활용하고 오버라이드 규칙 명시.
Section 03

2강 4개 케이스 스터디 비판적 해부 (토론 요약)

제4차 심화교육 2강(원본 2강 보기 ↗)의 4개 사례를 세밀히 검토한 결과, 임상적 직관으로 등급을 먼저 정한 뒤 한국형 알고리즘 점수를 결론에 맞춰 부여하는 패턴이 1·3·4번에서 확인되었습니다. 바로 이 지점들이 ADR 평가 봇에서 설정값으로 분리해야 할 핵심 변수들입니다.

사례 1. Daratumumab → IRR

강의: Probable (10점) / Non-serious
  • 합리적 측면: 코막힘·오한·발열·SpO2 저하·저혈압이 증속(50→200 cc/hr)과 맞물린 전형적 1st-dose IRR. 4증상을 하나의 증후군(IRR)으로 묶어 Bortezomib SC 등 병용약 가능성을 낮춘 점은 임상적으로 타당.
  • 허점 ① Dechallenge(+3) 오류: 실제로 중단한 적 없이 00:00까지 완료 투여했고, 00:15 BP 80/35는 종료 후 악화 + NS 1L·Hydrocortisone·O2로 회복 → 순수 Dechallenge는 0점.
  • 허점 ② 중증도 과소평가: 초기 호전 후 재발(18:25→21:15→00:15 BP 80/35)은 CTCAE v5.0 IRR Grade 3 기준(recurrence after initial improvement) 및 Serious 검토 대상.
  • 허점 ③ 병용약 경계선: 같은 날 새 약 7종(특히 15:30 Bortezomib SC) 동시 첫 투여 → 허가사항 기준 엄격 적용 시 Possible 가능.

사례 2. Pyrazinamide → 간독성

강의: Probable (12점→보정) / Serious
  • 합리적 측면 (4건 중 최우수): 한국형 총점이 12점(Certain 구간)임에도 PZA 미재투여를 이유로 WHO-UMC 기준에 맞춰 Probable로 하향 보정한 점은 교과서적.
  • 아쉬운 점 ① 단계적 증량 내성 착시: INH/RFP가 실제 원인이어도 소량 단계 증량(RFP 150→450, INH 100→300) + 실리만 유지 시 내성(adaptation)으로 간수치가 안 오를 수 있어 병용약 단독 배제(+2)는 다소 강한 해석.
  • 아쉬운 점 ② Lansoprazole 배제 근거 누락: 4/28~5/6 Lansoprazole 유지 중 LFT 정상화(31/39)라는 핵심 배제 논리를 명시했으면 완벽.
  • 미세 오류: AST 319(>5×ULN, G3)이나 ALT 173~185(ULN 40 기준 ~4.6×ULN, G2)인데 "둘 다 5배 초과"로 설명.

사례 3. Fosaprepitant → 두드러기

강의: Certain (16점) / Non-serious
  • 합리적 측면: Ramosetron→Palonosetron 교체 후 재발, Palonosetron 단독 무증상, 저속 주입 후 경미 재발로 교차 배제와 재투여 양성이 완결된 Certain 사례.
  • 허점 ① 과거력(+1) + 재투약(+3) 이중 계산: 원래 Allergy(-) 첫 노출이었으나 C1~C3 연속 에피소드를 과거력과 재투약 양쪽에 중복 가산(1점 제외해도 15점 Certain).
  • 허점 ② Dechallenge 교란: C1·C2-1은 항히스타민+스테로이드 투여 후 잔여 주입을 완료했는데 무증상. 순수 자연 호전 근거는 처치 없이 30분 만에 가라앉은 C3-1 쪽.

사례 4. Pethidine → 어지러움

강의: Possible (5점) / Non-serious
  • 허점 ① 단회 IV 주사에 Dechallenge(+3) 부여: 03:00 Pethidine 50 mg IV는 단회 주사라 중단 자체가 불가하며, 30분 만의 호전은 NS 1L 수액 효과. 1~4.5시간 뒤 BP 89/60 → 69/42로 오히려 악화 → 0점 또는 -2점이 타당(총점 5점 → 2점 또는 0점 Unlikely).
  • 허점 ② 지배적 비약물 원인: 투여 30분 전 이미 질출혈·혈종 제거·V/S 변화(94/69-94)가 있었고 Hb 11.5 → 7.9 → 6.3(2회 수혈)의 산후 급성 실혈 상황.
  • 허점 ③ 핵심 병용약 누락: 02:30 재시작한 경막외마취에서 Fentanyl만 조회하고 교감신경 차단 저혈압의 진짜 주범인 Ropivacaine을 누락. 권위 패널에서는 Unlikely 우세.
Section 04

ADR 평가 봇의 ‘주관성 세팅값’ 12대 축 (Configurable Policy Taxonomy)

평가자 간 이견이 발생하는 지점을 분석하면 아래 4개 그룹 · 12개 정책 파라미터로 구조화할 수 있습니다. 봇 배포 시 이 설정을 사용자(병원·지역센터·제약사·연구자)가 선택하게 만들면 "왜 이 등급이 나왔는가"에 대한 투명성과 재현성을 동시에 확보할 수 있습니다.

Group A. 평가 프레임워크 & 운영 목적 (Framework & Purpose)
파라미터 키설정 항목선택지 (Options)판정에 미치는 영향
primary_framework 기본 평가 체계 who_umc / korean_v2 / naranjo / ich_binary / organ_auto(DILI→RUCAM, SJS→ALDEN, 백신→AEFI) 출력 등급 체계(6단계 vs 이분법)와 전용 규칙 적용 여부를 결정.
algorithm_override 점수표 vs 임상 판단 충돌 who_override(미재투여 시 Certain 하향 등) / raw_score(알고리즘 총점 그대로) / conservative_min(둘 중 낮은 등급) 사례 2(12점)에서 Certain vs Probable 분기.
multi_suspect_mode 다약제 의심약 처리 single_primary(최유력 1종 선정) / multi_suspect(개연성 있는 약물 모두 Suspect 지정) 규제 보고(FDA/EMA/KAERS) 호환성 및 병용약 누락 방지.
Group B. 병용약 · 기저질환 · 증상 해석 (Confounders & Grouping)
파라미터 키설정 항목선택지 (Options)판정에 미치는 영향
concomitant_criterion 병용약 배제 기준 ★ strict_label(허가사항·문헌 기재 시 무조건 설명 가능) / clinical_plausibility(타이밍·제형·증후군·지속투여 종합) / ddi_aware(PK/PD 상호작용 별도 가산) 다약제 입원·항암 환자에서 Probable vs Possible을 가르는 최대 변수(한국형 +2 vs -3, 총 5점 격차).
symptom_grouping 다중 증상 통합 여부 syndrome_cluster(동일 기전 증상 통합, 예: IRR) / individual_pt(개별 MedDRA PT별 분리 평가) 사례 1에서 통합 시 Daratumumab 특이성 급상승, 분리 시 Bortezomib과 경합.
underlying_weight 비약물·기저질환 가중치 strict_alternative(출혈·감염 등 강력 대체원인 시 Unlikely 하향) / conservative_keep(시간 근접성 있으면 Possible 유지) 사례 4(산후 출혈 Hb 6.3)에서 Unlikely vs Possible 분기.
Group C. Dechallenge · Rechallenge · 과거력 (Temporal & Challenge)
파라미터 키설정 항목선택지 (Options)판정에 미치는 영향
dechallenge_policy 중단·감량 호전 인정 범위 ★ strict_pure(실제 중단+반감기 부합 자연 호전만) / moderate_clinical(응급처치 병행 시 조건부 인정, 단회·완료 투여는 0점) / lenient_lecture(단회·종료 후 호전도 +3점) 가장 빈번한 오채점 구간. 사례 1·3·4 모두에서 3~5점 변동 유발.
first_dose_rechallenge 1차 주입 특이반응 재투여 음성 exempt_zero(단클론항체 IRR 등 약리 특성 반영 0점) / penalize_minus2(기계적 -2점 감점) 사례 1처럼 첫 주입에만 생기는 IRR의 과도한 감점 방지 여부.
stepwise_reintro 단계적 증량 재도입 음성 해석 rule_out(재도입 무증상 약물 완전 배제) / uncertain_tolerance(탈감작·내성 가능성 고려해 배제 유보) 사례 2 항결핵제(INH·RFP 단계증량)의 병용약 배제 강도 결정.
prior_hx_dedup 과거력–재투약 중복 가산 disallow(동일 연속 사건은 재투약에만 반영) / allow(과거력 +1, 재투약 +3 동시 가산) 사례 3 같은 다주기 항암 반복 반응의 점수 인플레이션 방지.
Group D. 문헌 근거 · 심각도 · 결측치 (Evidence, Severity & Missing Data)
파라미터 키설정 항목선택지 (Options)판정에 미치는 영향
novelty_source 알려진 부작용 근거 범위 kr_label_only(국내 nedrug 허가사항) / global_ref(FDA·EMA·Micromedex·Lexicomp 포함) / case_and_signal(증례·실마리 포함) 신약·오프라벨 사용 시 Novelty 점수(+3 / +2 / 0) 변동.
seriousness_policy
(+ missing_data)		 심각도(Serious) & 결측치 정책 ctcae_g3_serious(법령 5항목 + CTCAE G3 이상 Serious 권고) / narrow_statutory(좁은 법령 해석) · 결측 시 conservative_conditional vs llm_infer 사례 1(BP 80/35 재발·IV 스테로이드)의 Serious 여부 및 정보 부족 시 환각(추론) 차단.

Section 06

      
ADR 평가 봇 실제 구현 아키텍처 & 배포 전략 제안

      
주관성 때문에 배포가 망설여진다면, "LLM이 등급 하나를 딱 찍어주는 봇"이 아니라 "명시된 정책 스키마에 따라 근거를 구조화하고, 세팅에 따라 결론이 갈리는 쟁점을 드러내 주는 의사결정 지원 봇(Decision-Support Bot)"으로 포지셔닝하는 것이 가장 안전하고 설득력 있습니다.


      

        

          
STAGE 1 · EXTRACT

          
구조화 타임라인 추출

          
자유 서술 의무기록에서 약물별 시작/종료/용량/제형, 증상 발현·재발 시각, 검사치, 응급처치를 JSON 타임라인으로 정규화.

        

        

          
STAGE 2 · RAG

          
공식 DB 근거 조회

          
nedrug 허가사항, FDA/EMA 라벨, 반감기, 대표 증후군 패턴(1st-dose IRR 등), DDI DB를 검색해 환각(Hallucination) 차단.

        

        

          
STAGE 3 · ENGINE

          
정책 기반 결정론적 평가

          
선택된 policy_config.json에 따라 한국형/WHO-UMC/RUCAM/ALDEN 규칙을 코드로 계산(LLM의 산술·규칙 오류 차단).

        

        

          
STAGE 4 · EXPLAIN

          
민감도 + 양면 리포트

          
최종 등급과 함께 "어떤 세팅을 바꾸면 등급이 바뀌는지"(예: Dechallenge 엄격 적용 시 Probable→Possible)를 자동 경고.

        

      


      

        
★ 배포 리스크를 줄이는 핵심 UX 아이디어: "Sensitivity Badge (민감도 표시)"

        
    
          
  • 강건한 판정(Robust): 세팅을 바꿔도 결과가 변하지 않음 — 예: 사례 3(Fosaprepitant)은 거의 모든 세팅에서 Certain.
    • 
          
  • 경계성 판정(Policy-Sensitive): 특정 세팅 1~2개에 따라 등급이 바뀜 — 예: 사례 1(Daratumumab)은 Probable ↔ Possible, 사례 4(Pethidine)는 Possible ↔ Unlikely. 봇이 "이 사례는 Dechallenge 인정 기준과 병용약 배제 기준에 민감하므로 전문가 확인이 필요합니다"라고 표시해 주면 오히려 신뢰도가 급상승합니다.
    • 
          
  • 면책 및 감사 로그(Audit Trail): 모든 평가 결과에 사용된 policy_config.json 버전과 스냅샷을 함께 저장하면, 병원·연구팀 간 일치도(Kappa) 비교 연구 도구로도 바로 활용할 수 있습니다.

5) 제품명(상품명) vs 성분명 표기 공식 기준 & 자동 병기 가드레일

      
실무에서 말하는 ‘상품명’은 식약처 공식 용어로 제품명(품목명)입니다. 구조화 코드 칸과 A4 서술문의 표기 기준을 분리하되, 추적성이 필수인 고위험 품목에는 자동 예외 가드레일을 적용합니다.

      

        

          
구분공식 기준 (식약처 · ICH E2B R3 · EMA GVP VI · CIOMS V)핵심 이유

          
            

              KAERS 구조화 입력칸
              식약처 허가 제품명(품목기준코드) 원칙 (모를 때만 성분명)
              동일 성분이어도 제형(서방정·주사제)·부형제(PEG·Polysorbate 80)·제조사 품질 차이 구분.
            

            

              바이오의약품 · 바이오시밀러 · 백신
              제품명 + 성분명(INN) + 제조번호(Lot/Batch) 필수 수준 (EMA는 누락 시 의무 추적 문의)
              성분명만 적으면 오리지널 vs 바이오시밀러 구분 불가 → 실마리 분석 왜곡.
            

            

              복합제 · 조영제
              제품명(성분명) 병기 권장 (예: 셉트린정(TMP-SMX), 울트라비스트(iopromide))
              배합비·삼투압·성분 식별을 동시에 확보.
            

            

              일반 단일 합성의약품 (서술문)
              사용자 선택 4옵션: ① 첫 언급 제품명(성분명) → 이후 성분명(추천) ② 항상 병기 ③ 성분명만 ④ 제품명만
              단, 제네릭 전환 후 발생·부형제 알레르기 의심 시 제품명 명시 필수.

의사·약사·간호사가 세팅하는 노코드 정책 & 3층 개인 문체 엔진

      
날짜·약물 표기 같은 큰 규칙은 코드로 제어할 수 있지만, "판단됨" vs "판단합니다", "병용약" vs "병용약제에 의한 발생가능성이 낮아" 같은 개인 고유 어휘·어미·호흡은 단순 체크박스로 담을 수 없습니다. 따라서 객관식 성향 퀴즈(판정 정책)와 주관식 작성 기반 3층 개인 문체 엔진(표현 습관)을 결합합니다.

      

        

          
① 주관식 작성 퀴즈 + Few-Shot 복제
문체 역추출

          
    
            
  • 복잡한 가상 사례 1건의 원시 팩트를 주고 평소 방식대로 상세내용/검토의견을 직접 주관식 작성(또는 기존 보고서 1~2건 붙여넣기).
    • 
            
  • LLM이 선호 어미(~판단합니다)·어휘 치환표(병용약→병용약제)·문장 호흡을 한글 스타일 카드로 추출하고, 작성 원문 자체를 Few-Shot 예시로 함께 주입해 말투 재현도를 극대화.
    • 
          

        

        

          
② 편집 Diff 자동 학습 (쓰면서 진화)
In-Context 학습

          
    
            
  • AI 초안("병용약 가능성 낮아 판단됨")을 약사가 A4에서 "병용약제에 의한 발생가능성이 낮아 판단합니다"로 고치면, 봇이 AI 초안 vs 최종본 Diff를 분석.
    • 
            
  • 반복 수정 패턴을 감지해 "내 문체 사전에 추가할까요? [등록]" 제안 → 일주일만 써도 본인 분신 같은 문체 완성.
    • 
          

        

        

          
③ 판정 성향 퀴즈 온보딩 (미니 사례 4개)
정책 자동 세팅

          
    
            
  • 추상적 토글 대신 2줄짜리 미니 사례 4개(병용약·단회주사·미재투여 12점·BP 80/35 심각도)에 "선생님이라면 어떤 등급?" 클릭.

  • 4번 클릭만으로 본인·병원 성향의 policy_config 자동 생성.
    •

팀 표준화

Section 09 · Clinical AI Safety

      
ADR 실무 특화 5중 환각 방지(Anti-Hallucination) 아키텍처

      
임상 문서에서 날짜·용량·검사치·8자리 코드 하나만 틀려도 보고서 신뢰도가 무너집니다. 다음 5중 가드레일을 시스템 차원에서 강제합니다.


      

        

          GUARDRAIL 01
          
원문 앵커링 (클릭 → A4 형광펜)

          
오른쪽 패널의 모든 판단 근거는 반드시 가운데 A4 원문의 정확한 구절(Quote)을 묶어 출력. 클릭 시 A4 원문이 하이라이트되어 원문에 없는 창작을 1초 만에 적발.

        

        

          GUARDRAIL 02
          
Closed-Set 강제 (코드 · DB · 산수 분리)

          
MedDRA 코드는 업로드 파일 후보 인덱스 중 선택만 허용(가짜 코드 0%). 허가사항은 공식 API 조회 결과만 인정(실패 시 미조회 표기). CTCAE 배수·알고리즘 점수는 100% 코드 계산.

        

        

          GUARDRAIL 03
          
숫자·날짜 불변성 자동 검증 (Post-Check)

          
문체 다듬기·번역투 교정 직후 원문 A4의 모든 숫자·날짜·용량·혈압(80/35, 319/173)이 최종본에서 변질·누락·신규 생성되지 않았는지 코드로 자동 대조 후 경고.

        

        

          GUARDRAIL 04
          
‘모름’ 강제 & 누락 체크리스트

          
A4 원문에 없는 사실은 추론 금지(무조건 정보 없음 0점). 대신 오른쪽 패널에 "⚠ 재투여 기록 없음 / 기저 eGFR 없음" 등 누락 정보 체크리스트를 별도 표시.

        

        

          GUARDRAIL 05
          
반대 가설 강제 생성 (Devil's Advocate · 확증 편향 차단)

          
LLM은 사용자가 의심약으로 지목한 약에 동조하는 편향이 강함. 내부적으로 "의심약이 범인이 아닐 가장 유력한 대체 원인(병용약·출혈·감염) 1가지"를 반드시 먼저 찾게 강제해 사례 4(산후 출혈·Ropivacaine) 같은 오판을 방지.

        

      

    


    
    

      
Section 10 · Windows Desktop & Multi-LLM Connector

      
Windows 병원 PC 배포 & IeumOffice형 멀티 LLM · API 연결 설계

      
병원 약제부 PC는 대부분 Windows 환경이며 관리자 설치 권한이 없거나 망분리·방화벽 제약이 존재합니다. IeumOffice처럼 가벼운 Windows 데스크톱 앱 + 표준화된 멀티 LLM 연결 어댑터로 설계합니다.


      
1) Windows 배포 전략 (병원 PC 친화)

      
    
        
  • 앱 프레임워크: Tauri(초경량 ~15MB, Rust 백엔드로 로컬 맞춤법·SQLite·암호화 직접 구동) 또는 Electron(IeumOffice와 동일 계열, Node/Chromium 생태계).
    • 
        
  • 무설치 포터블(.exe) 배포 우선: 관리자 권한(UAC) 없이 폴더 복사만으로 실행 가능. 모든 사용자 데이터(MedDRA 인덱스, 정책 프리셋, 평가 이력)는 로컬 SQLite DB에 저장.
    • 
        
  • 자격증명 보안: 입력한 API 키는 평문 파일이 아니라 Windows OS 기본 암호화(DPAPI / Windows Credential Manager)로 안전하게 로컬 저장.
    • 
      


      
2) IeumOffice형 멀티 LLM 프로바이더 연결 (OpenAI-Compatible 통합)

      
사용자가 설정 화면에서 드롭다운 1개로 모델 공급자를 고르고 API Key(또는 로컬 주소) 입력 후 [연결 테스트]만 누르면 즉시 전환되도록 단일 통합 어댑터로 추상화합니다.


      

        

          
연결 모드지원 프로바이더 / 엔드포인트보안 · 비용 특징권장 병원 환경

          
            

              1. 상용 API 직접 연결
              OpenAI (GPT) · Google Gemini(무료 티어 지원) · Anthropic Claude
              사용량 기반(Gemini는 무료 티어 가능). 전송 전 자동 비식별화 필터 옵션 제공.
              외부망 PC · 개인 연구 · 익명 증례 학습
            

            

              2. 엔터프라이즈 API
              Azure OpenAI · 병원 사내 AI 게이트웨이 (Custom Base URL + Header/Key)
              원내 계약·보안 정책 준수, 학습 미사용 보장.
              엔터프라이즈 LLM 도입 상급종합병원
            

            

              3. 완전 오프라인 로컬 LLM
              Ollama (localhost:11434/v1) · LM Studio (localhost:1234/v1)
              외부 전송 0% · 비용 0원. 분할 호출(추출→분석→서술)로 14B~32B 모델도 안정 구동.
              망분리 PC · EMR 원문 고보안 환경
            

          
        

      


      
3) 무료 의약품 DB API & 망분리 오프라인 폴백

      
    
        
  • 온라인 모드: 식약처 공공데이터 API(nedrug 허가사항·DUR) + openFDA + RxNorm/DailyMed + PubMed E-utilities 자동 조회 및 로컬 SQLite 캐싱.
    • 
        
  • 오프라인 / 망분리 모드: 인터넷이 막힌 PC에서도 동작하도록 사전 내장 정적 룰북(CTCAE v5.0, KIDS SAE 목록, R-ratio, R1 곁사슬) + 사용자 업로드 MedDRA 파일 + 로컬 캐시 허가사항 DB로 자동 폴백(Offline-first 설계).
    •
